# ○○지역아동센터 홈페이지

Django 6.1 / SQLite. 개발용 껍데기 단계.

## 실행
```
.venv/bin/python manage.py runserver
```

## 페이지
| URL | 설명 |
|---|---|
| `/` | 홈 (센터 정보 + 최근 공지 3건) |
| `/notices/` | 공지사항 목록·상세 |
| `/programs/` | 프로그램 안내 |
| `/about/` | 센터 소개·오시는 길 |
| `/attendance/` | 출결 키오스크 (타일 버튼 또는 번호 입력) |
| `/attendance/board/` | 출결 현황판·수기 수정 (직원 로그인 필요) |
| `/attendance/export/?month=YYYY-MM` | 월별 출결 CSV |
| `/admin/` | 관리자 (공지·프로그램·아동·출결 등록) |

관리자 계정은 직접 만든다 (비밀번호는 문서에 적지 않는다).

```
.venv/bin/python manage.py createsuperuser
```

## 출결 동작
아이는 **자기 타일을 누르거나** 번호를 치고 엔터. 기록이 없으면 입실, 입실만 있으면 퇴실,
이미 퇴실했으면 변경 없음.

번호는 두 가지를 다 받는다.
- **인식번호** — 보호자 번호 뒷 4자리. 남매는 뒤에 순번 한 자리 (2742 / 27421 / 27422).
  관리자 화면에서 아동마다 등록한다. 중복은 DB가 막는다.
- **출석번호** — 1~2자리. 인식번호와 자릿수가 달라 겹치지 않는다.

현황판은 날짜를 옮겨 다니며(`?date=2026-03-14`) 입실·퇴실 시각, 사유(출석/결석/조퇴/병가/기타),
비고를 직접 고칠 수 있다. 지난 날짜를 보정할 때는 알림톡을 보내지 않는다.
퇴실 누락분은 추정 시간을 자동으로 넣지 않고 현황판 상단에 경고로 띄운다 (정산 근거라서).

## 알림톡
`center/notify.py`의 `send_alimtalk()` 하나가 전부. 경기도 API 승인 전이라
실제 전송 없이 `NotifyLog` 테이블에만 기록한다. 승인 후 이 함수 안에서만 실제 호출을 추가하면 된다.

## 보안 설정
개발 기본값으로 돌아가고, 운영에서는 환경변수로 덮어쓴다.

| 환경변수 | 개발 기본값 | 운영에서 |
|---|---|---|
| `DJANGO_SECRET_KEY` | 공개된 더미값 | 임의의 긴 문자열 (유출 시 세션·비밀번호 재설정 토큰 위조 가능) |
| `DJANGO_DEBUG` | `1` (켬) | `0` — 켜 두면 에러 화면에 설정·코드·DB 내용이 노출된다 |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1` | 실제 도메인 |

`db.sqlite3` 에는 아동 이름과 보호자 연락처가 들어 있다. `.gitignore` 로 커밋을 막아 두었다.

## 아직 안 한 것
- 운영 배포 (HTTPS, 서버, 백업)
- 개인정보 처리방침
- 미입실 아동 보호자 자동 안내 (발송 시각 정책 미정)
- CSV 칸 구성이 지자체 보고 양식과 맞는지 확인 (현재는 참고용)
- 결석 아동 보호자 자동 안내
- 센터 실제 정보 (`config/settings.py`의 `CENTER`), 약도
