# 확인 사항 및 주의 사항

**아직 안 끝난 것**(외부 확인 대기, 사용자 결정 대기)만 표 한 줄씩 적는다. 작업 기록은 커밋·PR 본문에 둔다.
갱신 규칙은 [docs/README.md](README.md) 참고.

분류:

| | 뜻 |
|---|---|
| **A** | 사용자가 직접 확인 가능 (로컬 / 계정 / 실물 장비) |
| **C** | 외부 기관에 문의해야 확인 가능 |
| **D** | 배포 환경이 생겨야 확인 가능 |
| **E** | 확인이 아니라 결정 사항 |

---

## A. 사용자가 직접 확인

| 상태 | 항목 | 방법 | 비고 |
|---|---|---|---|
| ☐ | 운영 PC 디스크 암호화 | 시스템 설정 → 개인정보 보호 및 보안 → FileVault | **우선순위 높음.** DB 가 평문이라 분실 시 그대로 읽힌다 |
| ☐ | CSV 가 윈도우 엑셀에서 안 깨지나 | 내보내기 → 윈도우 PC 에서 더블클릭 | BOM 은 확인했으나 **맥에서만** 확인 |
| ☐ | 실제 넘버패드에서 입력되나 | 센터용 넘버패드 연결 후 타이핑 | 소프트웨어 키 입력으로만 확인됨 |
| ☐ | 터치 모니터에서 타일이 눌리나 | 터치 장비에서 확인 | 마우스 클릭으로만 확인됨 |
| ☐ | GitHub Actions 사용 가능 분수 | 레포 Settings → Billing | 무료 한도를 확인한 적 없다 |
| ☐ | 팀원 2명 프라이빗 레포 초대 | Settings → Collaborators | 초대 가능 인원 미확인 |

## C. 외부 문의 필요

항목별 문서는 [docs/외부문의/](외부문의/) 에 있다. 답을 받으면 해당 문서와 이 표를 함께 갱신한다.

| 상태 | 항목 | 문의처 | 문서 |
|---|---|---|---|
| ☐ | 경기도 알림톡 API 연동 | 경기도 담당 부서 | [알림톡-연동-문의서.md](외부문의/알림톡-연동-문의서.md) |
| ☐ | 출결 정산 보고 양식 | 지자체 / 상위기관 | [정산양식-확인요청서.md](외부문의/정산양식-확인요청서.md) |
| ☐ | 개인정보 수집·이용 동의 범위 | 센터 (기존 동의서) | [개인정보-확인요청서.md](외부문의/개인정보-확인요청서.md) |
| ☐ | 센터 기본 정보·운영 방식 | 센터장 / 담당 직원 | [센터-정보수집-질문지.md](외부문의/센터-정보수집-질문지.md) |
| ☐ | 보관·파기 기한 (성남시 기준, 5년의 기산점, 출결의 증거서류 해당 여부) | 성남시 아동 담당 부서 | 실제 데이터 투입 시점에 확인하기로 함. 문의서는 아직 안 씀 |

보관·파기 기한에 대해 법령 원문(law.go.kr, 2026-11-06)에서 확인한 것:
- 보조금 증거서류 5년 보관: 「보조금 관리에 관한 법률 시행령」 제10조의2. 대상은 「감사원법」 제25조의 계산서·증거서류이고, **출결 기록이 여기에 해당하는지는 미확인**
- 불필요해진 개인정보는 5일 이내 파기하고 파기를 기록: 「표준 개인정보 보호지침」(고시) 제10조
- 「성남시 지역아동센터 운영 및 지원에 관한 조례」 제1~20조에는 보존기간·파기 기준이 **없다**
- 그래서 기한이 확정되기 전에는 **아무것도 지우지 않고**, 용량을 이유로 자동 삭제하지 않는다. 퇴소 아동 익명화·파기 기능(`SECURITY_REVIEW.md` M-10)도 그때까지 만들지 않는다

## D. 배포 환경 필요 — 우선순위 낮음

도메인과 서버가 생긴 뒤에 확인한다.

| 상태 | 항목 | 비고 |
|---|---|---|
| ☐ | 실제 HTTPS 에서 리다이렉트·HSTS 동작 | 로컬에서는 301 까지만 확인됨 |
| ☐ | 리버스 프록시 뒤 `SECURE_PROXY_SSL_HEADER` 필요 여부 | 프록시 구성에 따라 다르다 |
| ☐ | `DEBUG=False` 에서 CSS 서빙 | whitenoise 또는 웹서버 필요 |
| ☐ | 백업 절차와 복구 테스트 | 암호화된 저장소에만 |
| ☐ | 세션이 4시간 뒤 실제로 만료되나 | 설정값만 확인함 |
| ☐ | 동적 취약점 스캐너 (ZAP 등) | 실습본은 팀이 로컬에서 돌리는 중. main 을 배포 환경에서 돌려 본 적은 없다 |
| ☐ | Tailwind CDN 판을 빌드한 CSS 로 바꾸기 | 지금은 브라우저가 jsdelivr 에서 스크립트를 받아 화면을 그린다(개발용 지름길). 배포 전에 바꾼다 |

## E. 결정 사항 — 우선순위 낮음

확인할 대상이 없고, 정해야 하는 것들이다.

| 상태 | 항목 | 선택지 |
|---|---|---|
| ☐ | 출결 화면(`/attendance/`) 노출 방식 | IP 제한 / 내부망 분리 / 기기 인증 |
| ☐ | GitHub Pro 업그레이드 | 브랜치 보호가 필요해지는 시점에 |
| ☐ | 보호자 계정 여러 명 연결 | 지금은 `Child.guardian` 외래키 한 개라 부모가 계정 하나를 같이 쓴다. 다대다로 바꾸면 모델·마이그레이션, `views.py` `my()` 소유권 필터, 테스트, admin 이 바뀐다. 실제 데이터가 쌓이기 전이 쉽다 |
| ☐ | HSTS preload 켤지 | 브라우저 preload 목록에 올리면 서브도메인까지 영구히 HTTPS 만 쓰겠다는 약속이라 되돌리기 어렵다. 지금은 `SILENCED_SYSTEM_CHECKS` 로 일부러 끈 상태. 도메인·HTTPS 운영이 확정된 뒤 결정 |
| ☐ | 키 관리 — 보관 위치·보유자·분실 시 복구 | 암호화 방식 설계는 `docs/개인정보-보호-설계.md`. 센터 사용 허락과 배포 확정 뒤에 정한다(후순위) |
| ☐ | 온라인 상담 예약 폼 | 하고 싶지만 보류(2026-11-16). 기능을 더 넣자고 하실 때 다시 꺼낸다. 지금은 전화 버튼만 있다 |
| ☐ | 식단표 | 홈의 "오늘의 건강 밥상" 카드는 화면만 있고 문구·사진이 견본이다. 누가 어떻게 입력할지 보류 |
| ☐ | 오래된 기록을 CSV 로 옮기기 | 지금 규모(아동 50명×5년 가정, 임시 DB 측정)에서는 DB 크기가 문제 된다는 근거가 없고, CSV 는 DB 밖에 아동 이름 파일을 새로 만든다. 당분간 안 함. 다시 볼 조건: 보관 기한 확정 / 실제 데이터에서 느려지는 것이 측정될 때 |

정해진 것:
- 완성될 때까지 **모의 값만** 쓴다. 실제 서비스 전환은 완성 후 사용자 허락을 받고 한다
- 아동 정보 암호화는 main 에서 해결한다(키 관리 설계가 먼저). vuln 은 평문 그대로
- 게시판·댓글·회원가입은 vuln 전용
- 실습본(vuln)은 실습할 수 있게 완성해 팀에 넘겼고 손을 뗐다(2026-11-16). 팀은 각자 도구로 진단·보고서 작성 중. 팀이 찾은 것은 `docs/발견-순환.md` 대로 main 에서만 다룬다. 팀에 더 넘길 일이 생겨도 `SECURITY_REVIEW.md`·취약점 목록·`docs/외부문의/`·`CLAUDE.md` 는 제외
- 이제 순서는 시큐어 코딩 → 배포 준비 → 실제 클라우드 환경에서 띄워 보기
- 화면은 새 시안(Warm Sprout)으로 통일한다. 시안의 "응원 수" 표시는 뺀다
- 활동앨범은 Pillow 없이 만든다. 사진의 위치 정보는 올리는 사람이 미리 지운다(2026-11-16)
- OWASP 번호는 2025판 기준

## 상시 주의 사항

작업할 때마다 지켜야 하는 것. 체크박스가 아니라 **규칙**이다.

1. **실습본을 인터넷에 올리지 않는다.** 취약한 서버는 제3자 공격의 발판이 된다.
2. **`db.sqlite3` 를 커밋하지 않는다.** 아동 실명·보호자 연락처가 평문으로 들어 있다.
3. **`logs/` 를 DB 와 같은 수준으로 다룬다.** `error.log` 에는 에러 추적에 요청 내용이 섞이고, `security.log` 에는 접속 IP 가 남는다.
4. **`SECURITY_REVIEW.md` 는 답안지다.** 실습본 브랜치에 포함하지 않는다.
5. **추정한 출결 시각을 자동으로 채우지 않는다.** 보조금 정산 근거다.
6. **테스트 통과를 "안전하다"로 바꿔 말하지 않는다.** 무엇을 확인했고 무엇을 안 했는지 구분해 적는다.

## 실제 데이터 투입 전 체크리스트

프로젝트 폴더는 집에서도 보려고 Google Drive 동기화를 켜 둔 **의도된 설정**이고, 지금 데이터는 전부 모의 값이다.
`.gitignore` 는 git 만 막고 Drive 동기화는 막지 못하므로, 실제 아동 정보를 넣기 전에 아래를 끝낸다.

- [ ] 프로젝트를 Drive 밖으로 옮기거나(예: `~/dev/jiacenter-web`), 이 폴더만 동기화 제외 — 코드는 GitHub 에 있으므로 옮겨도 잃을 것이 없다
- [ ] Drive 에 이미 올라간 `db.sqlite3` 삭제 (휴지통까지)
- [ ] Drive 버전 기록에 남은 사본 확인 — Drive 는 과거 버전을 보관한다
- [ ] `logs/error.log` 도 같이 정리 — 요청 내용이 섞일 수 있다
- [ ] **보관·파기 기한 확정** — 위 C 표 마지막 줄

이 항목이 정리되기 전에는 실제 아동 정보를 입력하지 않는다.
