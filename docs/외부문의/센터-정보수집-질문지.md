## 3. 출결 운영 방식 ★ 기능 설계에 직결

### 3-1. 수정 시점

- [ ] 출결을 **하루 중간중간** 고치시나요, **퇴근 전에 몰아서** 정리하시나요?

> 중간중간이면 현황판에 입력칸을 두는 게 맞고(현재 구조),
> 몰아서라면 `/admin/` 목록에서 쭉 훑으며 고치는 쪽이 빠릅니다.

### 3-2. 인식번호

현재 설계: 보호자 번호 뒷 4자리, 남매는 뒤에 순번 한 자리 (`2742` / `27421` / `27422`)

- [ ] 실제로 쓰시던 방식과 같은지
- [ ] 남매 순번을 부여하는 규칙이 따로 있는지
- [ ] 보호자 번호가 바뀌면 인식번호도 바꾸시는지

### 3-3. 미입실 아동

- [ ] 보호자에게 안내를 보낸다면 **몇 시 기준**이 적당한지
- [ ] 하루 1회면 충분한지
- [ ] 보내면 안 되는 경우가 있는지 (사전 결석 통보 등)

### 3-4. 출결 구분

현재: 출석 / 결석 / 조퇴 / 병가 / 기타

- [ ] 실제로 쓰시는 구분과 맞는지
- [ ] 더 필요한 항목이 있는지

### 3-5. 기록 수정 권한

- [ ] 출결을 고칠 수 있는 사람이 누구여야 하는지 (전 직원 / 담당자만 / 센터장 승인)

## 4. 장비 환경

| 항목 | 질문 |
|---|---|
| 현관 단말 | 노트북인지 태블릿인지, 터치 되는지 |
| 입력 장치 | 넘버패드 모델 (숫자 입력과 엔터만 되면 됩니다) |
| 네트워크 | 센터 인터넷이 고정 IP 인지 (출결 화면 접근 제한에 필요) |
| 직원 PC | 몇 대인지, 공용인지 |

- [ ] 현관 화면을 외부 방문자가 볼 수 있는 자리인지 — **개인정보 노출 범위와 직결**
