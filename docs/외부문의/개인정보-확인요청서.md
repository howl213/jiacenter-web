## 1. 시스템이 다루는 개인정보

| 항목 | 저장 위치 | 쓰는 곳 | 누가 보나 |
|---|---|---|---|
| 아동 성명 | `Child.name` | 키오스크 화면, 현황판, CSV | **누구나** (키오스크는 로그인 없음) |
| 출석번호 | `Child.number` | 키오스크 타일 | 누구나 |
| 인식번호 | `Child.code` | 키오스크 입력 | 직원 (화면에 표시되진 않음) |
| 보호자 연락처 | `Child.guardian_tel` | 알림톡 발송 | 직원 |
| 등·하원 시각 | `Attendance` | 현황판, CSV | 직원 (키오스크에도 당일분 표시) |
| 출결 사유 | `Attendance.status` | 현황판, CSV | 직원 |
| 발송 예정 알림 내역 | `NotifyLog` | 확인용 | 직원 |

저장 형태: SQLite 파일(`db.sqlite3`) **평문**. 별도 암호화 없음.

## 2. 확인이 필요한 사항

### 2-1. 기존 동의서 범위

- [ ] 현재 보호자에게 받는 동의서에 **출결 전산 관리**가 포함되어 있는지
- [ ] **보호자 연락처를 알림 발송에 쓰는 것**이 동의 범위에 있는지
- [ ] 제3자 제공·처리 위탁 항목이 있는지 (알림톡은 외부 서비스를 경유합니다)
- [ ] 동의서에 적힌 **보유 기간**

### 2-2. 아동 성명 노출 범위 ★

현재 키오스크(`/attendance/`)는 **로그인 없이** 재원 아동 전원의 성명과 당일 등·하원 시각을
보여줍니다. 아이가 자기 칸을 눌러 출결을 찍는 구조이기 때문입니다.

- [ ] 현관에 둔 화면에 **아동 실명을 그대로 표시해도 되는지** 센터 방침
- [ ] 외부 방문자(택배, 상담 오신 학부모 등)가 지나다니는 자리인지
- [ ] 마스킹(`김○○`)이 필요한지 — **기능은 구현했다가 "센터 내부 전용"이라는 전제로 해제한 상태**입니다.
      되돌리는 데 한 줄이면 됩니다

### 2-3. 보유와 파기

- [ ] 퇴소 아동의 성명·연락처를 언제까지 보관하는지
- [ ] 출결 기록은 정산 증빙으로 더 오래 보관해야 할 수 있는데,
      **개인정보는 파기하고 출결만 익명화해 남기는 방식**이 가능한지
- [ ] 파기 방법과 기록 의무

### 2-4. 접근 통제

- [ ] 아동 정보를 **누가 열람할 수 있어야 하는지** (센터장만 / 모든 직원 / 담당 교사만)
- [ ] 열람 기록을 남겨야 하는지 — **현재 남기지 않습니다**
- [ ] 직원 퇴사 시 계정 처리 절차

### 2-5. 처리방침

- [ ] 개인정보 처리방침을 홈페이지에 게시해야 하는지
- [ ] 센터에 이미 작성된 처리방침이 있는지
