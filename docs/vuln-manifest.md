`scripts/check_leaks.sh --external` 이 `docs/` 를 막는다. 팀 저장소에는 올리지 않는다.

규칙
- 취약점 하나 = 커밋 하나. 커밋 메시지는 `vuln(A0N): ...` 로 시작한다
- 심은 커밋은 그 항목을 지키던 테스트를 "취약함이 있다"는 테스트로 바꾼다
- `main` 에서 이 커밋을 되돌리면 조치 diff 가 된다 (팀 W9, S2 제안)
- OWASP 번호는 Top 10:2025

## 실행 확인

- 2026-11-10 `docker compose up --build` 로 실행: `/`, `/notices/`, `/attendance/`, `/login/` 이 모두 200, 컨테이너 `Up`, 포트는 `127.0.0.1:8000` 에만 열림. 사용자가 브라우저에서 첫 화면(실습 배너, 센터 정보, 모의 공지 3건)을 확인함
- 확인하지 못한 것: 심은 취약점 항목별 실제 동작(화면으로), 로그인 이후 화면, 컨테이너 안에서의 `migrate`·`seed_dummy` 출력 전체
- 같은 날 이 폴더에서 Django 시험 52개(3개 건너뜀) 통과, 하네스 시험 48개 통과, 개인정보·갈래·목록 검사 통과

> main 에서 합쳐 올 때 `SECURITY_REVIEW.md`(답안지)가 다시 들어오면 `scripts/check_track.py` 가 실패한다. 충돌이 나면 삭제를 유지한다.

## Windows 계보에서 합친 항목 (2026-11-13)

Windows 에서 만든 `vuln/practice` 의 커밋 12개를 이 계보로 합쳤다. 같은 약점을 양쪽이 각자 심은 두 곳
(공지 검색 SQL 삽입, 공지 서식 XSS)은 위 표의 `vuln(A05)` 구현 하나만 남겼다. 나머지는 모두 살렸다.
라벨은 그 계보의 커밋 이름 그대로이며, 위 표의 OWASP 2025 번호와 다를 수 있다
(예: 그 계보의 `A03` 은 저장형 XSS). 분류는 팀이 진단하며 다시 정한다.

| 항목 | 커밋 | 어디 | 무엇을 열었나 |
|---|---|---|---|
| A07 | `vuln(A07) 회원가입 — 가입 요청이 보낸 권한 값을 그대로 믿음` | `center/views.py` `signup()` (`/signup/`) | 가입 요청에 `is_staff` 를 넣어 보내면 직원 권한으로 가입된다 |
| A03 | `vuln(A03) 게시판·댓글 — 본문을 이스케이프 없이 출력` | `center/views.py` `post_detail()` | 글·댓글 본문을 `mark_safe` 로 그대로 출력한다(저장형 XSS) |
| A01 | `vuln(A01) 내 아이 조회 — URL 의 child id 로 소유자 검사 없이 조회` | `center/views.py` `my()` | `/my/?child=<남의 id>` 로 남의 아이 출결이 보인다(IDOR). `/my/<id>/` 는 위 A01 |
| A01 | `vuln(A01) 외부 임베드 — 사용자 URL 을 서버가 검증 없이 가져옴` | `center/views.py` `embed()` | `/embed/?url=` 로 서버가 임의 URL 을 가져온다(SSRF) |
| A07 | 위 `vuln(A07)` 회원가입 커밋에 딸려 있어 따로 커밋이 없다(2026-11-13 실습 항목으로 올림) | `center/views.py` `signup()` (`/signup/`) | `signup()` 이 폼을 거치지 않아 `AUTH_PASSWORD_VALIDATORS` 가 돌지 않는다. 한 글자 비밀번호로도 가입된다 |

URL 충돌로 옮긴 것: 위 A06 전화 인증 가입은 `/signup/phone/` 으로 옮겼다(`signup_phone()`). `/signup/` 은 Windows 계보의 아이디·비밀번호 가입이다.
