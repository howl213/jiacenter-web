### 실습판에 심은 취약점 (vuln/practice_v1)

삽입 목록(`docs/vuln-manifest.md`) 기준 **취약점 17건** (기본 12 + Windows 계보에서 합친 5). 삽입 목록은 팀 공개 전까지 비공개 문서다.

| OWASP | 건수 | 예 |
|---|---|---|
| A01 접근 통제 | 4 | CSV 직원 검사 제거+IDOR(`/my/<id>/`), IDOR(`/my/?child=`), 게시글 수정·삭제 작성자 확인 없음, SSRF(`/embed/`) |
| A02/A04 | 2 | 기본 관리자 계정·DEBUG, MD5 해시 |
| A03 | 1 | 게시판·댓글 저장형 XSS |
| A05 | 2 | 공지 검색 SQL 삽입, 공지 서식 XSS |
| A06 | 1 | 전화 인증 가입(인증번호 3자리·시도 제한 없음·번호 노출) |
| A07 | 4 | 시도 제한 제거, 세션 고정, 회원가입 권한값 신뢰, 가입 비밀번호 규칙 없음 |
| A08 | 1 | 업로드 검사 없음 + `role` 쿠키로 현황판 권한 상승 |
| A09 | 1 | 로그인 실패·열람·CSV 기록 안 함 |
| A10 | 1 | 현황판 입력 검증 제거 |

(건수는 삽입 목록의 표 행(12 + 5)을 센 값이다. 한 행에 두 약점이 묶인 곳(CSV+IDOR 등)은 1건으로 셌다. 이 표에서는 A02 와 A04 를 한 줄로 합쳤다.)

### 현재 진행률

**아직 숫자를 확정하지 못했다.** 팀이 정한 분모(전체 목표 기능 수)가 있으면 그것으로 계산한다.
임시로 로드맵 기준이면: 0~4단계 5개 완료 + 5단계 4개 중 3개 완료 = 8 / 10 항목 (6·7단계 제외). 6·7단계를 포함하면 계산이 달라진다.

## 태스크 1. 팀원별 작업 내용 설명 (본인 몫)

> 본인이 맡은 부분만 남기고 나머지는 지운다. 아래는 저장소에서 확인되는 작업 목록이다.

**main (안전한 껍데기)**
- 시도 제한: 로그인·키오스크 번호를 연속으로 틀리면 잠근다 → 무차별 대입 차단
- 보호자 계정: 보호자가 로그인해 자기 아이의 최근 30일 출결만 본다 (`/my/`, 다른 아이는 못 봄)
- 공지 첨부: PDF·PNG·JPG만, 공지당 3개, 파일당 5MB. 내용(앞부분 바이트)까지 검사
- 보안 로깅: 로그인·잠금·현황판 열람·CSV 내보내기/가져오기를 `logs/security.log` 에 기록
- 하네스: 위험 명령 훅, 개인정보·갈래 검사, 작업 규칙 자동 주입

**vuln (실습판)**
- 취약점 삽입: 위 표의 항목을 "취약점 하나 = 커밋 하나"로 심고, 그 항목을 지키던 시험을 "취약함이 있다"는 시험으로 바꿈
- 팀 전달용 내보내기: 심은 곳 설명 주석과 답안지를 제거한 복사본 생성

각 항목은 **무엇을 → 왜 → 어떻게(파일·함수) → 결과(스크린샷)** 4줄로 쓴다.

### B. vuln (실습판) — 로컬에서만, 포트 8000 (main 서버를 끄고 실행)

준비. `db.sqlite3` 가 0바이트라 마이그레이션과 모의 데이터가 먼저 필요하다. `seed_dummy` 는 로컬 DB를 바꾸므로 훅이 한 번 묻는다:

```bash
cd ../mini-projetct-vuln
../mini-projetct/.venv/bin/python manage.py migrate
../mini-projetct/.venv/bin/python manage.py seed_dummy
../mini-projetct/.venv/bin/python manage.py runserver
```

| # | 화면 | 주소 | 보여 줄 것 |
|---|---|---|---|
| B1 | 실습 배너 | `/` | "취약 실습판" 배너가 보이는 첫 화면 |
| B2 | A06 인증번호 노출 | `/signup/phone/` | 응답 화면에 인증번호가 그대로 나옴 |
| B3 | A07 세션 고정 | `/?sessionid=abc` | 개발자도구 쿠키 탭에 `abc` 가 세션으로 잡힘 |
| B4 | A01 IDOR | `/my/?child=<남의 id>` | 남의 아이 출결이 보임 |
| B5 | A03 저장형 XSS | `/board/posts/` | 모의 스크립트(`alert`)가 실행된 팝업 |
| B6 | A05 SQL 삽입 | `/notices/?q='` | DB 오류 화면(DEBUG 켜짐) |
| B7 | A01 SSRF | `/embed/?url=http://127.0.0.1:8000/` | 서버가 자기 자신을 가져온 결과 |
| B8 | A09 기록 없음 | 터미널 | 로그인 실패 뒤 `logs/security.log` 에 새 줄이 없음 (main 은 줄이 생김 — A7 과 비교) |

B 번호는 삽입 목록에 적힌 위치(주소·함수)를 근거로 했다. 각 화면의 실제 동작은 이번에 서버를 띄워 확인하지 않았다 — 찍으면서 안 되는 것이 있으면 알려 주면 코드를 보고 고친다.

## 최종 정리 순서

1. A 먼저 찍고 main 서버를 끈다 → B 를 찍는다.
2. 각 스샷 밑에 "무엇을 / 왜 / 어떻게(파일·함수) / 결과" 한 줄씩.
3. 미션 화면 "하위 태스크"에서 태스크 1·2 각각에 붙여 제출.
