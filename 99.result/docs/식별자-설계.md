# 주소 속 번호(식별자) 설계

> 상태: **설계만 있고 코드는 안 바꿨다** (2026-11-17). 근거는 `src/center/views.py`·`urls.py`·`models.py` 를 직접 연 결과다.

## 1. 무엇을 정하는 글인가

주소에 들어가는 번호를 어떻게 할지 정한다. 지금은 `/albums/3/` 처럼 1, 2, 3… 순서 번호(`<int:pk>`)다.
어떤 사이트는 `/education/OY7uSMMQiWYckpxGfb/…` 처럼 **짐작할 수 없는 임의의 글자**를 쓴다.

## 2. 임의의 글자를 쓰는 이유와 한계

- 순서 번호는 숫자만 바꿔 가며(`/albums/4/`, `/albums/5/`…) 남의 것을 열어 보기 쉽다. 이 공격이 IDOR 이고 OWASP A01(접근 통제 실패)에 든다.
- 임의 값은 다음 값을 짐작할 수 없어서 이 훑어보기를 어렵게 한다.
- **하지만 보안의 주인공이 아니다.** 주소를 알게 되면(공유·기록·어깨너머) 그대로 열린다. 진짜 방어는 서버가 매번 "이 사람이 이걸 볼 권한이 있나"를 확인하는 것이다. 임의 값은 그 위에 덧붙이는 보조 장치다.

## 3. 지금 우리 코드 (직접 확인한 것)

| 주소 | 번호 | 누가 보나 | 판단 |
|---|---|---|---|
| `/notices/<pk>/`, `/notices/files/<pk>/` | 순서 번호 | 누구나 (공개 글) | 바꿀 이유 없음 |
| `/albums/<pk>/`, `/albums/photos/<pk>/` | 순서 번호 | 누구나 (공개 글) | 바꿀 이유 없음 |
| `/my/` | **주소에 번호 없음** | 로그인한 보호자 | 이미 좋은 방식. `Child.objects.filter(guardian=request.user)` 한 줄이 남의 아이를 막는다 (`views.py` `my()`) |
| `/attendance/` 키오스크 | 폼에 아동 `pk` | 로그인 없음 | 문제는 번호 모양이 아니라 **로그인이 없는 것**(`확인사항.md` E 의 노출 방식 결정, `SECURITY_REVIEW.md` A01). 화면에 아동 전체가 이미 나오므로 임의 값으로 바꿔도 얻는 것이 없다 |
| `/attendance/board/`, 내보내기, 명단 가져오기 | 폼에 아동 `pk` | 직원(`@staff_member_required`) | 권한 확인이 이미 있음 |

- 공지·앨범·프로그램에는 "공개 여부/임시저장" 칸이 없다(`models.py` 에서 `published`·`draft` 등을 찾았으나 없었다). 지금은 올린 글이 모두 공개다.

## 4. 제안하는 설계

1. **지금은 바꾸지 않는다.** 공개 글은 순서 번호여도 문제가 없고, 비공개 데이터는 이미 주소에 번호가 없다.
2. **권한 확인을 1순위 규칙으로 못 박는다.** 소유자가 있는 자료는 조회할 때 소유자 조건을 **같이** 건다(`filter(guardian=request.user)`). 번호만으로 `get_object_or_404(Model, pk=…)` 하지 않는다.
3. **새로 소유자가 있는 자료를 만들 때만 임의 값을 붙인다.** 예: 상담 예약, 보호자-센터 메시지, 아이별 상세 화면(`/my/children/<id>/`).
   - 모델에 `public_id = UUIDField(default=uuid4, unique=True, editable=False)` 를 따로 두고, 주소는 `<uuid:public_id>`, 안쪽 순서 번호는 주소에 내지 않는다.
   - 없는 것과 남의 것 모두 **똑같은 404** 를 준다(존재 여부를 알려 주지 않는다).
   - 시험을 먼저 쓴다: 다른 보호자가 접근하면 404.
4. **공개 글에 "임시저장/비공개"를 넣게 되면** 임의 값이 아니라 `published` 칸을 두고 조회에서 걸러 낸다. 번호를 짐작해도 비공개 글은 안 나오게 하는 것이 원칙이다.
5. 하지 말 것: 번호를 해시하거나 base64 로 바꾼 값(되돌릴 수 있거나 짐작 가능), 짧은 임의 값.

## 5. 바꿀 때 드는 비용 (기존 자료에 적용한다면)

- 이미 있는 행에 칸을 더하고 값을 채운 뒤 유일 조건을 거는 3단계 마이그레이션이 필요하다.
- 주소가 바뀌어 기존 링크가 끊긴다.
- 그래서 **실제 데이터가 쌓이기 전에** 정하는 편이 쉽다. 지금 공개 글에는 필요 없다.
